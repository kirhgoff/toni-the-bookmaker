1. Context and current state

What exists today, and what this proposes to add.

toni is a CLI that turns PDFs and text files into audiobooks: extract text → chunk at sentence boundaries → synthesize each chunk through a TTS engine → concatenate with ffmpeg into an MP3. Work is resumable through a manifest.json tracking per-chunk status, and parallelised with a multiprocessing.Pool where each worker loads its own model.

Shortly before this design, the OmniVoice engine (k2-fsa/OmniVoice, 0.6B params, 24 kHz, ~RTF 0.38 on MPS) was added as --model omni, and four pre-existing bugs were fixed — a sentence splitter that mis-split non-ASCII text, concurrent manifest corruption, nested retry-splits being dropped from the output, and a stale manifest cache that broke --workers 2 entirely.

This report designs an opt-in audio-play mode: detect characters, infer their attributes, give each a distinct voice, render dialogue in that voice and narration in a narrator voice. Target language is English only.

Why English-only changes the design fundamentally

English has mature, purpose-built tooling for exactly this problem that other languages lack — so the right move is to use a library rather than build a parser. English also makes OmniVoice's ten accent attributes usable (they are English-only in the model), expanding the distinct-voice space from 50 combinations to 1,000.

The offsetting loss: languages with gendered past-tense verbs hand you each speaker's gender for free. English gives nothing per-utterance. That loss is recovered at the character level, not the utterance level — see §6.

2. How this design was produced

Propose, attack, revise. The attack mattered.

An architect agent produced a design; an adversarial reviewer then attacked it, verifying every load-bearing claim against the repository, the installed package, BookNLP's source and model server, and the published literature. It raised 15 findings — 2 blockers, 7 serious, 6 minor. The architect accepted all 15, with one nuance.

The blocker worth understanding

Round 1 justified the whole approach with the claim that BookNLP is "near-perfect on explicit quotes." That is false for the version you can install. The ~98% figure belongs to systems retrained on PDNC with SpanBERT-large — research artifacts, not packages. The pip-installable model, whose weights are dated November 2021, scores 64% on explicit quotes.

Had this gone unchecked, the design would have trusted a component that misattributes roughly one in three tagged quotes — producing exactly the failure this architecture treats as unacceptable: a confident, wrong character voice.

The second blocker was an omission rather than an error: the design never stated what fraction of dialogue actually gets a character voice. That number decides whether this is an audio play or an audiobook with occasional funny voices, and it is now §5.

3. Tooling decision: BookNLP, but only for part of the job

Use the library where it is strong; refuse it where it is weak.

BookNLP (UC Berkeley, MIT-licensed code) is purpose-built for literary text: quote detection, character name clustering, coreference, and referential gender inference. Writing an English quote segmenter, alias clusterer and coref system by hand would be roughly 1,500 lines of subtle code that ends up worse than a model trained on annotated fiction.

But the revised design discards BookNLP's speaker-attribution output entirely and uses only its inputs:

JobWho does itWhy
Quote span detectionBookNLPHandles straight/curly/single quotes and dominant-symbol detection per book
Character clustering & aliasesBookNLPMr. Darcy/Darcy/Fitzwilliam → one entity. String matching would not suffice
Character genderBookNLPAggregates thousands of pronoun-coref links per character — statistically strong
Speaker attributionOur code, deterministicBookNLP scores 42% here. Not usable.
Character age / pitch / accentLLM (one call, optional)No library provides this; it is cheap and quality-critical

Attribution is re-derived in about 150 lines of stdlib: a quote is attributed only when the same sentence contains speech-verb + proper-name mention in either order, resolved through BookNLP's token and entity offsets rather than raw regex over text.

Hard constraint that shapes the architecture

BookNLP is transformers-4.x-era code; omnivoice 0.2.1 requires transformers>=5.3.0. They cannot share a virtualenv. BookNLP therefore runs in a pinned side environment invoked by subprocess — which conveniently also keeps it off toni's default dependency path. Its tokenizers pin has no cp312 wheels, so that side environment is locked to Python ≤ 3.11 and uv must provision a second interpreter.

5. How much dialogue actually gets voiced

The number the first design never computed. It decides whether this feature is worth building.

Three attribution sources are in scope, all deterministic and all high-precision by construction:

  • Explicit tags — "…," said Mary. The reliable core.
  • Multi-paragraph continuation — an unclosed quote followed by a paragraph opening with a quote continues the same speaker. Gated to double-quote-dominant books only (see below).
  • Two-party alternation — where explicit tags establish exactly two speakers in a run and no third named mention intervenes, untagged quotes alternate. This is how a human reads Hemingway, and it attacks the implicit class exactly where it concentrates.
Book typeExplicit tags only+ continuation + alternation
Tag-heavy (children's, much YA)60–85%80–95%
Classic ensemble (Austen, Dickens)25–45%50–75%
Sparse-tag two-party modern (Hemingway-like)10–25%50–80%
No quote marks (McCarthy, Saramago)~0%~0% — play mode refuses

These are estimates to be replaced by spike measurements. Without alternation, the left column is the product — and for an Austen novel that means two-thirds of dialogue read by the narrator.

Inconsistency is its own defect

A low but erratic voicing rate may be worse than none: the same character flipping between their own voice and the narrator line-by-line within one scene is more jarring than a straight narrator read. The design treats this as a defect class and applies a scene-level all-or-nothing rule — if fewer than half of a character's quotes in a dialogue run are attributed, the whole run is demoted to narrator.

--prep-only prints per-book coverage (percentage voiced, per-character breakdown, demoted runs) and recommends against play mode below a floor (default 40%). Whether a given book is worth rendering as an audio play becomes a measured, printed number — decided before any audio is generated.

6. The pipeline

extract → book classifier → BookNLP (subprocess, isolated env) → deterministic attribution + continuation + alternation → consistency demotion + same-voice merge + typed pauses → [casting call: age/pitch/accent] → capture voices (.pt) → existing Pool → existing ffmpeg concat green = deterministic, 0 tokens amber = library orange = LLM

Prep runs once and writes artifacts to work/<stem>.play/ — a separate directory from simple mode, so a plain run and a play run of the same book cannot collide. (Work dirs are keyed by output stem only; without this, a play-mode prep followed by a plain run would silently resume the play manifest and emit a mangled hybrid.) Resume reads the artifacts and never re-runs BookNLP or the LLM.

The book classifier

A one-page preflight that prints what play mode can and cannot do for this book, rather than silently degrading: quote-mark density and dominant symbol, first-person detection, named-character density. Books without quote marks are refused with an explanation.

Where gender comes from

Not from verbs — English has none to offer. From BookNLP's book-level referential gender: thousands of aggregated pronoun-coref links per character, cross-checked against a twenty-entry honorific table (Mr./Mrs./Miss/Sir/Lady/Lord). This uses coreference where it is statistically strong (aggregate) rather than where it is weak (resolving a single he said — that branch was cut for exactly this reason).

Non-speech quote filter

English introduces a false-positive class that dash-based conventions don't have: scare quotes, quoted titles, he called it a "disaster". A span shorter than five tokens, mid-sentence, with no speech verb in its sentence, is demoted to narration.

Single-quote British editions

Where ' is both quote mark and apostrophe, boys', 'tis, 'em and goin' corrupt open/close tracking. This matters most for the continuation rule, which keys on "unclosed final quote" — a miscount turns a narrator fallback into a false speaker-continuation chain, i.e. a wrong-voice error. Continuation is therefore enabled only for double-quote-dominant books in v1.

7. The interruption problem

The most common dialogue shape in English fiction, and the design's biggest unresolved risk.

"I think," he said, "that we should go."

Naively this becomes three chunks and two voice switches. Because each fragment is synthesized independently, "I think," receives sentence-final falling intonation and "that we should go" cold-starts a new sentence. Austen and Dickens produce thousands of these per novel.

Two treatments go to a listening test before the pipeline is built:

  • T1 — three segments with 0 ms pauses and minimized pad/fade.
  • T2 — merge the quote halves into one character-voiced generation and move the tag after it: "I think, that we should go," — he said. Semantically identical, prosodically continuous, and standard audiobook practice. It also cuts chunk count, which doubles as the render-cost mitigation.
If both fail

Voiced dialogue would be restricted to uninterrupted quotes, and the coverage table in §5 drops accordingly. That would be a real ceiling on the feature, and it is stated as one rather than discovered later. This is why the listening test is gate S6 and happens in stage 0.

8. Voice casting

Design once, freeze, clone forever.

OmniVoice's voice design samples a random voice matching the requested attributes on every call, with no seed parameter — useless across a worker pool, where every process would invent a different Elizabeth Bennet. So each voice is designed once, rendered to a short calibration clip, and frozen as a serialized VoiceClonePrompt (.pt). All rendering clones from that file: stable across processes, runs and machines, and measurably faster per chunk (2.65s → 1.34s).

A useful consequence: a per-character voice is just a file path, so it rides the existing generate(text, voice_sample: Path) signature. The TTSEngine ABC never changes and pocket/kani never learn this feature exists.

Pass the reference text

When building calibration prompts, supply ref_text= — we wrote the calibration sentence, so we know it. Omitting it makes OmniVoice load Whisper large-v3-turbo (~1.6 GB) to transcribe audio we generated ourselves.

The attribute space

Gender (2) × age (5) × pitch (5) × accent (10 + none) = 550 cells, with categories mutually exclusive. Enforcing unique (gender, age, pitch) tuples alone gives 50 cells — ample for any sane cast. Assignment is greedy by quote count, maximizing distance in attribute space, so major characters get maximally separated voices.

Accents are used conservatively. The casting call infers the book's home accent (British for Austen, American for Steinbeck) and applies it to narrator and cast by default; a character deviates only on textual evidence. A randomly-assigned Japanese-accented Mr. Collins is a worse defect than two slightly similar voices.

Play mode is omni-only; --play with pocket or kani exits with a clear error, since cloning-from-prompt is the mechanism everything rests on.

Render cost

Simple mode packs 300-character chunks; play segments are 40–150 character dialogue lines, plus interruption splits — 2–4× the chunk count. Per-generation cost with clone reuse is ~1.34s fixed, regardless of text length, so fixed overhead times chunk count dominates. Honest estimate: 1.5–3× simple mode, measured in stage 0 rather than asserted. A same-voice merge (combining adjacent segments sharing a voice) is the main defense; T2 interruption merging is the second.

10. Install footprint and licensing

The honest claim

The default install and default command path are unchanged. "Zero new dependencies" is not accurate: --play adds the play extra and provisions a ~2–3 GB side environment (second Python ≤3.11, torch-CPU, transformers ~4.30, spaCy model) plus ~1.1 GB of BookNLP model weights.

Model hosting is a single point of failure. Weights download from a personal faculty homepage over plain HTTP, with no checksums, no mirror, and no modification since November 2021. Mitigation: download once, verify against SHA256 hashes pinned in our repo, cache locally. No vendoring or mirroring until licensing is clarified — the MIT license covers the code repository; the weights' license is unstated and their redistributability is unverified.

Prep runtime is unmeasured. BERT-base coreference over 100k words on CPU is plausibly 20–60 minutes, one-time per book. No figure is quoted until the spike produces one.

12. Cost

PassCost per 100k-word novel
Stage 1 — no LLM at all$0.00
Casting call (one request)$0.03 – $0.10
Optional attribution refinement, cheap model, batched$0.04 – $0.17
Optional refinement, mid-tier model with adaptive thinking$0.25 – $1.50 (upper bound genuinely unpredictable)

The "minimize tokens" requirement is met structurally — a library does the bulk and the LLM sees at most a fraction of the book, once — rather than by prompt golf. Two caveats: batch discount and prompt caching are alternatives, not stackable, and caching buys little here because book text is sent once rather than repeatedly; and adaptive-thinking tokens bill as output, which is what makes the mid-tier upper bound unpredictable. Attribution from a provided scene is not deep reasoning — use a low effort setting or a cheaper model.

13. Staging plan

Stage 0 — Spike and plumbing

Gates S1–S9. Ships regardless of their outcome: typed pauses, pad/fade overrides, .pt support, resume mode guard, separate play work-dir keying. Independently useful — the resume guard fixes a latent hazard in simple mode today.

Stage 1 — Voiced audiobook $0 LLM

Deterministic explicit attribution, gated continuation, alternation (if S4 passes), consistency demotion, deterministic casting, coverage report with floor.

Honest framing: for tag-heavy and two-party books this genuinely is an audio play. For ensemble classics it is an audiobook where a majority of dialogue is voiced. Below the floor, prep tells the user not to bother. "Worth listening to" is a per-book measured claim printed by prep, not a marketing line.

What would have to be true for stage 1 to be universally worth listening to: anaphoric and implicit attribution at ≥95% precision — which only S8 or stage 3 can supply.

Stage 2 — LLM casting call

Ages, accents, first-person narrator gender. Plus wheel-install packaging.

Stage 3 — Conditional

LLM attribution refinement for anaphoric/implicit quotes, built only if S8 rejected ModernBookNLP. Killed unbuilt if S8 passed — which is the point of evaluating it first.

14. Out of scope and open questions

Book classes this cannot serve
  • No quote marks (McCarthy, Saramago, Ulysses) — zero quotes detected. Play mode refuses rather than silently producing a plain audiobook and reporting success.
  • Unnamed major characters ("the man", "the boy" in The Road; the narrator of Rebecca) — the cast requires proper names, so these are never voiced at any stage.
  • First-person narrators — no third-person pronouns coref to the narrator, so referential gender is empty for the protagonist. Policy: protagonist speech renders in the narrator voice, which is the correct audiobook convention. This is now a deliberate decision rather than an accident of the filter.

Open decisions

  1. Is a 50–75% voiced rate acceptable for the books you care about? If your library is Austen-shaped, that is the realistic stage-1 outcome. If it is dialogue-heavy modern fiction, alternation pushes it higher. This is the question the whole feature turns on, and it is worth answering before stage 0.
  2. Interruption handling. T2 reorders speech and tag. It is standard practice and prosodically better, but it does change the audio's word order relative to the page.
  3. Risk appetite for BookNLP. Dormant since 2024, weights from 2021 on a faculty homepage with an unstated license. The fallback backend exists, but it is meaningfully worse.
